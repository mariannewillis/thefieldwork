### The two rules this system will not bend

**Context-locked colour.** Magenta `#C2187A` ONLY inside a blush pool (3.45:1 on
the dark plate fails AA; 5.18:1 in a pool passes). Gold `#E9C87E` ONLY on the
dark plate (10.89:1 on dark; 1.47:1 in a pool fails). Swapping them is a
legibility failure, not a style choice.

**Hard edges.** Zero border-radius everywhere except Avatar (--radius-full, true circle) and pill-shaped nothing else — no rounded-md, no rounded-lg, no rounded-full on buttons/cards/inputs. Zero box-shadow everywhere (all --shadow-* tokens resolve to 'none'); the hard cut edge of the pool against the plate/ground is the only elevation cue this direction uses. Any generated primitive shape that introduces a radius or shadow beyond this law is a misread of the mockups.

## 3 · Voice + copy

Voice: plain, declarative, unhurried. Second person. Sentences of 8–17 words.
Adjectives are suspect; procedure is reassurance. The audience skews 35–65 —
assume the reading glasses are in another room.

- Button labels + headings + metadata labels: Sentence case.
- Body copy: full sentences ending with a period.
- Never: Elevate · Seamless · Unleash · Next-Gen · Empower · Transform your.
- Never invent a practitioner surname. She is **Marianne**. Her training and
  years are UNVERIFIED per brief §20.1 — do not state them as fact.

## 7 · Canonical chrome (from the gate-3 preview — the operator approved THIS)

_(preview declared no explicit footer bg — contract omitted)_

### Canonical dark-band text vocabulary

Inside any dark block, text colours are limited to: `text-text-inverted`.
NEVER use `text-text-secondary` / `text-text-tertiary` / `text-neutral-{700..950}`
/ `text-black` on a dark ground — they are mid-grey on near-black and fail AA
even though the token name suggests "secondary text".

### Pattern inlining inside dark contexts

The extracted patterns were lifted from light-pool sections and carry light-bg
text tokens. When inlining one into a DARK section, swap:
`text-text-primary`→`text-text-inverted` · `text-text-secondary`→`text-text-inverted/70`
· `text-text-tertiary`→`text-text-inverted/50`.

### Layout shell — MECHANICALLY AUDITED (D8). Every screen, no exceptions.

- **The nav/header element MUST be positioned** — `fixed`, `sticky`,
  `relative` or `absolute` on the `<header>`/`<nav>` itself. A static
  header fails D8. Marketing uses an absolute overlay on the hero plate; admin
  uses a fixed 256px sidebar rail.
- **Every content container MUST carry a width cap** — `max-w-[1280px]` (or
  `max-w-screen-xl`). A screen with no cap fails D8. Put it on the main
  content wrapper, not on `<body>`.
- **The footer MUST be structured** — a grid (`grid-cols-2/3/4`) or an
  explicit flex row. A single-line footer fails D8.
- Admin: 256px fixed sidebar rail, 11 nav items, active row inverts to the pool fill.
- Logo: `../../../assets/brand/logo-horizontal.svg` as an `<img>`. Never redrawn,
  never followed by a text wordmark span.

### The context lock is AUDITED (D11) — not advisory

`text-accent-500` (magenta) on a dark plate is a FAILING finding, caught
mechanically. Magenta lives inside a blush pool and nowhere else. On the dark
ground use `text-secondary-500` (gold) or `text-text-inverted`. This is the
single most repeated drift on this project — check every label you place on the
dark chrome before you write it.

### NEVER define an @keyframes (D9)

Two screens have already failed this: one wrote `service-detail-drift`, another
`workshop-detail-drift` — both 24-second infinite scale animations that exist
nowhere in the kit. The ONLY permitted keyframes are the kit's canonical set.
This direction is motion_intensity 3: fades on already-visible content, nothing
else. If you find yourself writing `@keyframes`, stop.

### The classes agents keep dropping (D1)

Real failures so far, all "it looked cosmetic": `pointer-events-none`,
`inset-0`, `decoration-1`. And do NOT swap a pattern's inline utilities for a
bespoke CSS class — one screen used `class="main-field"` where clearing-plate
specifies its utilities inline. Visually identical, structurally a bypass, and
the audit catches it.

### Patterns are inlined BYTE-FOR-BYTE (D1) — including utility classes

D1 compares your inlined pattern against the kit bytes and reports any missing
anchor class. Dropping a class you judged cosmetic — `pointer-events-none`,
for instance — is a D1 failure. Copy the block; do not tidy it.
